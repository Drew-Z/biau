# 展示设计：独立青珑、短提示、研究对话

## 推荐形态

页面右下角保留青珑本体，透明背景，无常驻包围框、描边或状态文字。角色与页面之间仅保留自然的脚下阴影。默认沿用桌面 96px、手机 72px 的 CSS 画布作为起点，按实际可见轮廓验收；不因截图物理像素直接放大。设置可提供小/标准两档，首版不依赖可调尺寸。

三个独立表面：

- **角色层**：一个常驻宠物实例，负责站立、动作、点击和移动。
- **气泡与操作层**：气泡锚定宠物上侧，最多两行；鼠标悬停或键盘聚焦可看到“对话/更多”的小操作区。两者都在角色外部。
- **聊天层**：桌面窗口优先放在宠物上方偏左，与角色保留至少 12px 间隙。标题是“青珑 · 研究助手”，不再放第二只动画宠物。正文、来源、输入、历史和错误均保留现有功能。

视觉独立不意味着完全没有 DOM 容器。透明的定位与语义按钮仍负责命中、焦点和无障碍，但不得绘制截图那种包住角色和文字的外壳；透明区域也不得吞掉周围网页点击。

## 默认交互

| 场景 | 角色 | 气泡/操作 | 对话 |
| --- | --- | --- | --- |
| 阅读、未提问 | idle，小幅既有动画 | 默认无常驻文案；聚焦可见“打开研究助手” | 关闭 |
| 背景 health 正在准备或失败 | 保持 idle | 不弹“准备中/等待重试” | 用户打开后如实显示连接状态 |
| 点击角色 | 保持原位，聚焦响应 | 收起冗余气泡 | 打开并聚焦输入；只做 health/必要恢复，不发送问题 |
| 用户提问后的真实处理中 | thinking/working/review | 关闭面板时可短暂显示真实阶段 | 展示现有进度和停止操作 |
| 等待用户补充 | waiting | 简短说明需要补充 | 具体问题与输入留在面板 |
| 回答完成且未读 | happy 只播放一次，随后 idle | “整理好了”短提示与未读徽标 | 打开后才按现有规则标记已读 |
| 实际请求失败 | failed 一次后平静停留 | “暂时没连上，点我查看” | 持久错误说明、保留草稿、显式重试 |
| 关闭面板 | 宠物继续留在原位 | 按真实活动显示 | 保留会话/草稿/进行中请求语义 |

“health ready”仅说明服务准备，“answer ready”才说明回答完成，两者不能共用完成动画或文案。被动失败的静默只影响外部表现，错误证据与面板提示仍保留。

气泡普通存活 6 秒；hover/focus 暂停倒计时，Escape 可收起。动画不逐帧播报到 aria-live；必要消息只播报一次。错误详情不依赖限时气泡，保留在对话内；所有操作都有可访问名称。

## 移动与空间

桌面 pointer 位移超过 6px 才进入拖动，拖完不触发点击；释放后吸附最近左右侧，位置保存为边和归一化高度。恢复、缩放和 resize 时重新夹紧到安全区。键盘通过“移至左侧/右侧、恢复默认位置”获得等价能力；是否增加方向键微调在第二批实现时按复杂度判断。

手机首版不自由拖动，使用左/右停靠选项，避免抢占页面滚动。点击打开独立底部对话层；软键盘或窄屏模态对话打开时，隐藏外部宠物的绘制及交互，不销毁实例。关闭后恢复原位置与焦点。

布局优先保证输入、关闭、发送、文章阅读导航和页面主操作可用；空间不足先隐藏短气泡或收起角色，不挤压对话正文。借用现有 collision/mobileSurface/visualViewport 逻辑，并在读取页和页脚实测。用户隐藏宠物后，导航/站点设置保留“显示青珑”的可见恢复入口；隐藏偏好与聊天关闭是不同状态。

## 实现边界与复用

建议由 App 保持一个稳定的 PublicAssistantCompanion 宿主，拆分出角色命中层、气泡/操作层以及独立聊天面板。PublicAssistantPet 继续只消费活动与一次性完成反馈，不承担网络、业务重试或第二个活动状态机。

当前 Widget 内持有 petTasks；实施时需把这一个活动聚合实例提升到稳定宿主并传给 Widget。Widget 继续维护会话、请求、恢复、Branch、Revision 和草稿，仅将已有事件投影到共享活动实例。不要为了外观把整个聊天业务状态搬进 App。懒加载前后消费同一实例，解决 Launcher→Widget 的宠物重挂载与完成反馈重复。

透明角色、气泡和面板可通过同级元素或 portal 组织，具体取决于现有 z-index/focus 关系；判据是独立定位、不受互相尺寸挤压且只有一个可见/运行的宠物。全局透明覆盖层设置 pointer-events:none，具体可交互元素自行启用命中。

需要检查的现有文件：App、PublicAssistantLauncher、PublicAssistantWidget、PublicAssistantPet、public-assistant-pet.css、flow-pages.css、route-pages.css、usePublicAssistantCollision、publicAssistantInterfaceCopy、publicAssistantPetActivity 及相应 UI fixture。不修改模型网关、免费实例配置、业务请求预算或刚上线的阅读预热调用边界。

## 分批交付

1. **展示职责拆分**：独立角色与聊天窗、移除大胶囊、保留单一角色生命周期；修正预热与真实任务的外观映射。
2. **陪伴交互**：短气泡、未读提示、桌面移动、隐藏/恢复；补齐手机安全区与键盘替代操作。
3. **视觉与行为验收**：三主题、两语言、各断点、生命周期与请求边界，完成本地截图审阅后再按发布计划上线。

八状态素材与现有播放器足以完成首版；不新增宠物框架。每批都能按 Git 中的精确文件差异回退，保留请求与会话数据。
