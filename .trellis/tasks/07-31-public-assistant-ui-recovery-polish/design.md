# Design

## Boundaries

- `PublicAssistantWidget.tsx` 保留现有状态、焦点和会话行为，只在必要时补充结构 class 或可访问性属性。
- `flow-pages.css` 负责模态层、原生控件、全屏网格、消息滚动列和编辑器 containment。
- `publicAssistantAgent.ts` 继续作为生成重试的唯一决策点；模型渠道顺序仍由 `model.ts` 决定。
- fixture 检查覆盖视觉结构契约和三次尝试矩阵，不访问外部服务。

## Layout

助手面板维持七行网格。全屏时面板本身填满视口，但所有对话相关行共享一个居中的内容列；消息区使用 `minmax(0, 1fr)` 吃掉剩余空间并独立滚动，composer 不使用 fixed/sticky 脱离布局。历史抽屉在面板内部建立隔离层，使用解析后的实色 token，避免 `color-mix(... transparent)` 让内容穿透。

## Recovery

总尝试数仍为 3：主通道、备用模型一、备用模型二。`nextModelChannelRelation()` 继续标记独立提供商和同故障域模型。重试矩阵新增一个窄规则：只有当前失败发生在备用提供商、下一次仍是同故障域模型时，`400/422` 才允许继续；`409/413`、取消和策略拒绝仍终止。该规则不增加端点探测或模型目录调用。

每个真实请求在开始时冻结一次渠道顺序，避免并发结果或本次失败让同一请求重复/跳过模型。进程内健康表只消费真实回答结果：成功清除熔断，认证/网络/超时/限流/上游/空响应等失败按类别设置有界冷却。健康通道保持配置中的质量顺序；冷却通道被移到末尾并在仍有健康通道时跳过。全部通道冷却时只选择最早可恢复的一条，避免故障扇出。Render 重启会清空健康表，避免陈旧状态永久影响路由。

## Rollout

先运行本地 fixture、lint、build 和截图检查，再提交推送。Render 关闭自动部署，因此必须手动触发 public assistant 服务部署并用 `/health` 与 revision 核对；不通过真实问题测活。

## Rollback

前端回滚仅需撤销组件/CSS提交。恢复策略回滚为原有 `400/409/413/422` 全部停止；环境变量和数据库无需改动。
