# 助手健康接口故障诊断

## Goal

让助手健康巡检的失败与恢复过程可定位。历史 Actions 只留下 HTTP 502，无法区分响应报告的代理连接失败、无效响应和普通 HTTP 错误；本任务修复诊断证据丢失，不承诺消除尚未查明的外部故障。

## Requirements

- 识别现有代理的五个固定错误码，保留响应类型和每次尝试的状态、耗时、失败类别。
- CI 汇总携带本次健康检查的低敏记录；未知错误文本、响应正文、地址、请求头不得进入新增证据。
- 保留当前最多五次检查、十五秒间隔、原超时及恢复后 degraded 的语义；默认不执行聊天或其他业务 POST。
- 旧报告继续可读；跳过步骤或无本次报告时，不能把历史尝试当成本次证据。
- 健康响应读取有大小和时间边界；默认检查不改变公开快照。

## Acceptance Criteria

- [x] 固定代理错误码、未知错误、JSON/HTML/空响应/坏 JSON/过大响应、慢正文和网络异常均有确定性验证。
- [x] 真实子进程汇总保留失败及恢复的完整安全尝试记录，覆盖历史报告、跳过和崩溃情况。
- [x] 专项合同、lint、build 通过；公开快照哈希不变，真实模型与业务 POST 为零。
- [x] 云端只读复核及其结果落档；外部故障与诊断修复的结论分开陈述。

## Notes

- 用户已多次授权按顺序解决剩余问题，本轮“继续”覆盖创建和推进此项修复；不重复请求相同许可。
- 原始故障证据：Actions run 42654767766，main-site 健康 HTTP 502，约 62.2 秒。后续浏览器路径健康 GET 返回 200；本机另一访问路径仍出现失败，不能据此认定全站持续故障或冷启动原因。
