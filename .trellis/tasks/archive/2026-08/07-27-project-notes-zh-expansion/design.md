# 项目技术档案中文深化设计

## 内容边界

- 保留 `docs/project-notes/` 的八文件结构，避免破坏已有索引和证据路径。
- 描述性文字全部中文化；Evidence label、代码符号、文件路径、URL、SHA 和稳定 scope 值不翻译。
- 所有生产表述继续受 `evidence-register.md` 的标签强度约束。

## 题库生成模型

- 新增结构化题库源与生成脚本，按主题对象生成 Markdown，避免手工维护 300 个重复块。
- 每个主题包含机制、决策原因、替代方案、失败信号、恢复策略、安全边界、验证方式和证据 ID。
- 每个主题固定生成五个互补角度：机制、权衡、故障恢复、安全边界、验证证据。
- 主题分配：Chatus 13、Anchor 12、公开助手 12、AI 日报 13、跨项目 10，共 60 个主题、300 组问答。

## 文档契约

每组生成结果使用稳定标题 `### QA-<SCOPE>-NNN`，正文包含：

```markdown
- 范围: chatus
- 问题: ...
- 深入追问: ...
- 参考回答: ...
- 失败场景: ...
- 验证方式: ...
- 证据: E-CHATUS-...
```

校验器要求精确数量、连续编号、字段最低长度、Evidence ID 存在、scope 与 ID 前缀一致，并拒绝旧英文问答字段。

## 风险控制

- 生成脚本只消费仓库内结构化数据，不访问网络或模型。
- 题库输出可重复生成，生成后仍由文档契约、Lint、Build 和差异检查验证。
- Chatus、公开助手和 AI 日报的敏感字段只描述抽象边界，不记录真实配置或生产内部标识。
