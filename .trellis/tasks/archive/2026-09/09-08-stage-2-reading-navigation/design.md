# 阅读导航恢复设计

## 状态与边界

新增一个复用 hook 模块，为目录和详情分别提供小型生命周期入口。目录/详情位置记录各最多 40 个，按 Router location key 区分同地址的不同历史条目。目录记录规范 href、稳定内容标识、实际焦点入口类型、入口相对视口位置及视口尺寸；详情只记录该条目的滚动位置。Map 不驱动业务渲染，不作为第二份筛选状态，也不写 localStorage/sessionStorage。

详情 Router state 仅携带来源 key。返回 Link 增加显式返回标记，相关同类 Link 传递来源 key；跨到博客/项目的另一类型链接仍使用各自规范入口，不传错类型来源。读取 state 时集中窄化 unknown，并用已存在的内存记录和规范目录 href 复核；无法匹配时走标题回退。

## 目录进入与返回

BlogCard 的卡片与按钮、ProjectCard 的按钮使用稳定内容标识。页面在导航事件内同步记录原入口位置，再通过 `navigate(..., { state })` 打开详情。键盘从博客卡片本身进入时恢复卡片；从按钮进入时恢复按钮。项目卡片的指针入口回到其现有详情按钮，不新增嵌套键盘角色。

目录仅在直接来自详情的 POP 或显式详情返回时安排恢复。详情卸载时核对实际目的地址；目录为本次 location key 保留一次转换判定，以兼容 Strict Mode effect 重放。筛选/搜索的 PUSH/REPLACE、从状态等其他路由返回都保留原行为。恢复后把同一位置关联到新的目录 history entry，后续继续浏览与历史切换互不覆盖。同尺寸按原入口的布局位置定位，忽略入场/按压动画的临时 transform；尺寸变化或动作原在固定导航之外时将入口带入有效视口。失效或隐藏入口回到可程序聚焦的 h1。ProjectsPage 初始 matchMedia 状态同步读取并保留事件清理，避免恢复到即将隐藏的桌面初始布局。

## 详情生命周期

详情在真实内容或缺失态就绪后执行一次导航定位。新 PUSH 无 hash 时定位顶部并聚焦 `tabIndex={-1}` 标题；真实 hash 定位已渲染目标；POP 有详情位置记录时恢复该位置。直接打开/刷新没有内存记录的详情保留浏览器初始语义，显式返回依然聚焦有效目录标题。

通过路由拥有的 effect/animation frame 完成 DOM 定位，离开或重放时清理。等待期间的真实指针、键盘、触控、滚轮输入取消迟到的自动定位，避免异步博客正文抢回操作。详情监听滚动及导航前交互，记录当前条目的位置；不修改全局 scrollRestoration 或 root scroll-behavior，不对状态/Studio 等路由安装恢复逻辑。

项目首图没有固定内在高度，晚到会改变正文之前的布局；实际延迟 fixture 复现已恢复位置从 770 增至 1130。POP 位置和真实 hash 等待本详情 eager 图片的 load/error 后再定位，不等待懒加载图片；新 PUSH 的标题聚焦立即执行。等待期间的用户操作仍取消自动定位并接管位置记录，卸载时移除图片监听。

## 验证与取舍

复用两个 URL 工具及既有网络隔离检查，不升级到 Data Router 或新增全站恢复服务。浏览器检查直接断言 activeElement、入口几何位置、scrollY、URL 和实际控制操作。延迟正文使用本地构建资源 fixture，不请求生产。包含普通动效、延迟取消、哈希、失效来源及不同历史条目，防止只检查返回 URL 的伪覆盖。

新 hook 同时影响共享卡片和两个详情生命周期，最终运行新版完整 UI 与 smoke，确保既有阅读指南、移动触控、目录和状态组均通过。回滚点是本项独立提交，前两项 URL 条件功能保持独立。
