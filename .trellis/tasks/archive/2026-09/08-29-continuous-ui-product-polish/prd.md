# 持续 UI 产品化审计与完善

## Goal

持续提升 `blog-semi` 产品官网的真实使用质量：围绕首页、项目、案例、博客、详情和状态路径，在桌面/移动、三种主题、中英文和主要交互状态下，通过浏览器证据发现并修复高置信度、用户可见且影响主路径的 UI 问题。

## Background

- 当前仓库是 React 19 + Vite + TypeScript + class-based CSS + Lucide 的产品官网，不是个人作品集或营销模板。
- 公开主路径包括 `/`、`/projects`、`/projects/:id`、`/blog`、`/blog/:slug`、`/status` 及相关公开 AI Daily 路径。
- 三个主题契约为 `morning`、`nature`、`stellar`；主题根属性和现有背景渲染 owner 必须保持一致。
- 当前 `main` 工作区基线为 `5fd98f56`，启动本任务时工作区干净；任何后续用户改动都必须保留，不得覆盖或清理。

## Requirements

### R1. 基线与证据

1. 开始每轮前记录 `git status --short --branch`、HEAD、worktree 和已有差异。
2. 启动本地开发服务器，用 Playwright 或浏览器实际检查真实页面，不以静态代码推断替代视觉证据。
3. 每轮覆盖桌面和 `320`、`390`、`430` 移动宽度；覆盖 `morning`、`nature`、`stellar`、中文和英文状态。
4. 维护按严重程度排序的 UI 问题清单，状态至少包括待处理、处理中、已验证、暂缓；每轮保存修改文件、验证命令和浏览器结果。

### R2. 产品体验范围

审计并在有可靠证据时修复：

- 首页第一视口的产品定位、公共状态摘要、首个项目卡和 CTA；
- 导航层级、当前页面状态、移动端主导航、主题和语言控制；
- 首页到项目、案例、博客、详情及状态页的内部/外部路径；
- 标题、正文、辅助信息、卡片、筛选、搜索、标签、空/加载/错误状态的层级与一致性；
- 间距、对齐、边框、阴影、图标、hover/focus/disabled/pressed 状态；
- 长文本、中英文切换、窄屏溢出、遮挡、横向滚动和触控区域；
- 浅色/暗色（三主题）对比度与视觉一致性；
- 键盘操作、焦点可见性、语义标签、ARIA 和基础无障碍。

### R3. 实施边界

- 优先复用现有令牌、class-based CSS、组件和 `lucide-react`；不引入新的 UI 框架或无依据的大规模重构。
- 不伪造业务数据、客户结果、截图、评价或产品能力；缺少素材时使用稳定克制的占位方案。
- 不修改 `public/status/blog-semi-synthetic.json`，不读取/写入密钥，不部署、签名、发布或推送。
- 不删除、回滚、清理其他活动 worktree，不使用 `git reset --hard`、`git clean -fd` 等破坏性命令。
- Codex 保持主协调、最终审查、集成和验收职责；Claude（若启用）一次只负责一个独立 leaf，使用专用 worktree，不与主工作区并行修改相同文件。

### R4. 品牌主标对照实验

- 在不替换生产导航 Logo、favicon 或项目图标的前提下，由 Codex 与 Claude Code 各自独立重新生成一套原创 SVG/CSS 候选；上一轮 V2 仅作为未发布历史，不再作为当前对照终点。
- 两套 V3 候选使用相同的 `64 × 64` 网格、安全区、主题材质和动效规则，以黑白轮廓、`24/40/48/64px` 及 `morning/nature/stellar` 对照进行选择。
- Port、海洋和公开边界通过字母内腔、开放切口和状态节点表达，不直接描摹船、帆、锚、波浪、罗盘或既有品牌。
- `B/b` 只作为隐约的重心和节奏来源，不得闭合成标准字体式字母，也不得退化为通用 App 方块或图标模板。
- 实验页只作为未发布的设计评审面，不加入主导航、项目目录或 sitemap；主标确认后再单独规划生产替换与项目子标家族。

## Acceptance Criteria

- [ ] 每轮问题清单有证据、严重程度、状态和明确的保留/暂缓原因。
- [ ] 每个已修复 leaf 都有可审查 diff、文件所有权检查和浏览器回归证据。
- [ ] 受影响路径在桌面、`320`、`390`、`430` 宽度无横向溢出、重叠或不可达 CTA。
- [ ] 三个主题都保持可识别的独立视觉系统，主题切换、刷新持久化和 Logo/导航状态正常。
- [ ] `/studio/brand/logo-lab` 可并排比较 Codex V3 与 Claude Code V3 的彩色、单色、小尺寸和三主题版本，且不改变生产 Logo。
- [ ] 中英文切换后主要标题、按钮、标签和导航仍可读且不溢出。
- [ ] 相关交互具备语义元素、键盘可达、可见焦点和至少 44px 触控目标（适用处）。
- [ ] 每轮最低门禁通过：`npm.cmd run lint`、`npm.cmd run build`、`npm.cmd run check:ui`、`npm.cmd run check:ui:smoke`、`git diff --check`；涉及背景/大资源时追加 `npm.cmd run performance:check`。
- [ ] 只有当不存在值得立即修复的高置信度 UI 问题、需要用户素材/产品决策或出现无法本地解决的外部阻塞时才结束任务。

## Out of Scope

- 后端/API/数据库/模型能力、公开状态数据真实性和部署基础设施本身；仅处理其在前端的明确呈现问题。
- 真实业务素材补充、信息架构大改、全站设计系统替换；实验页之外的生产 Logo 替换与项目子标部署本轮暂不执行。
- `public/status/blog-semi-synthetic.json` 及其他不属于本轮 UI leaf 的生成状态文件。

## Open Questions

无。用户已授权持续执行，要求不因单个 leaf 完成而停止；若发现需要真实素材或产品决策，再将其列为阻塞并暂停该分支。
