# 公开路由恢复设计

助手建议是可降级的界面辅助功能，不应使路由的缺失态失效。继续在 `assistant.ts` 保持唯一建议来源，新增一个私有的安全片段解码函数，只捕获 `decodeURIComponent` 对损坏输入的异常并返回 null。详情查找失败沿用默认三个建议；前缀匹配、尾斜杠处理和正常路径保持原语义，不反复解码或创建路由别名。

状态详情的既有标识是 `pet-gamer`。只改 publication 的错误引用；registry 检查使用真实 `reliabilityProjects` 集合加 `/status` 总览建立允许路径集合，避免字面前缀放过不存在的目标。不改状态数据、项目状态或 sitemap，也不增加临时重定向。

确定性检查覆盖有效、未知、编码、双重编码和损坏编码的建议选择；registry 检查先在旧错误记录上失败。浏览器检查接入原 check-ui 分组并可单独运行，复用网络 guard，所有 API 使用本地失败 fixture；不会发送真实问题或生成请求。坏地址通过已加载 SPA 的 history 导航复现，确保助手先挂载，再让 React 处理异常路径；早期直接访问诊断只记录 launcher 点击超时，没有证据归因到 preview 中间件。助手关闭但已挂载也要覆盖。合法详情断言限定 level 1 标题，避免导航提交前匹配目录卡片中的同名 h3。

最终 UI 保留缺失页、全局导航和返回操作，history 后退仍可读目录。普通编码详情保持特定建议。状态引用逐个打开现有总览/详情并核对标题，帆灵错误来源必须被纠正。整个范围不改变布局、文案事实或生成产物，回滚单位为本子任务提交。
