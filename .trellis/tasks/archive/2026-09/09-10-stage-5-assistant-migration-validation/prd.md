# 公开助手本地 PostgreSQL 迁移验收

## 目标

在一次性本地 PostgreSQL 容器验证已有公开助手修订迁移，记录空 schema、历史数据保真、归属触发器和清理结果；不连接生产数据库或修改公开内容。

## 依据与范围

- 第 25 轮迁移检查因缺少测试数据库 URL 未执行；第 29 轮确认本机 Docker 29.3.1 正在运行，并缓存 PostgreSQL 18.4 镜像。
- 复用 `scripts/check-public-assistant-revision-migration.mjs`，在独立的一次性数据库运行四份既有迁移，验证空 schema 与旧版会话升级。
- 容器仅绑定 loopback 的临时端口，使用 tmpfs 数据目录和本轮生成的临时凭证；连接值只存在当前进程，不写 `.env`、源码或文档。
- 本项只交付验收证据、父子任务记录及 journal。若出现实现失败，保存原始证据并由父任务独立定界，不直接修改迁移或生产逻辑。
- 既有持续本地授权覆盖本项；主会话执行，不调用真实模型或生产数据库。

## 验收

- [x] 确认使用已缓存镜像，未拉取依赖、未连接远端 Docker 或生产数据库。
- [x] 空 schema 创建两类修订/分支表和全部 7 个触发器。
- [x] 旧数据升级保留回答、引用、指标、时间、会话/分支、反馈和幂等响应；旧字段按既有迁移删除。
- [x] 修订更新和跨归属写入被拒绝，整会话级联删除通过；既有检查实际 exit 0。
- [x] 检查器创建的临时 schema 已清空，任务容器已移除，既有容器与卷保留。
- [x] 原源码、迁移及保护快照未变；精确本地提交后仅归档本子任务并实际返回父任务。

## 不在范围

不修改应用源码、迁移、生产配置或公开内容；不读取私有环境文件、不连接 Supabase/Studio/生产数据库、不调整 RLS、不执行生产迁移、不推送、部署、开启 Feed/Cron 或重建 heartbeat。PostgreSQL 18.4 本地通过不等于生产版本或服务已验收。
