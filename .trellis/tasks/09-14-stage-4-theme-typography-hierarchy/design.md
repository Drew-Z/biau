# 三主题文字层级与卡片配色设计

## 决策与实施顺序

采用一个有四个验证节点的子任务：覆盖修复 → 文字与控件 → 内容空间 → 回归交付。先恢复设计令牌的正确归属，再校准外观，防止选好的颜色被旧规则覆盖。四个节点共同组成一个可验收结果，不预建多个相互等待的任务。

## 1. 恢复分类色与材质归属

- 去除首页公共卡片规则对分类强调色的重复赋值，让原 signal/preview/commerce/image 映射生效。
- 分类仅提供 accent 与必要的材质变量；共用规则消费变量。Stellar 通过统一 token/规则投影材质，避免 variant 选择器让主题规则只对 signal 生效。
- 整理本次相关的 background、border-color、border-left-color 声明，避免简写再次覆盖分类边框。只合并相关规则，不顺带重写整份历史 CSS。
- 节点结果：四类卡片的 computed accent、序号色、基础背景和边框来源可解释；三主题均有四种分类色，交互状态不会丢失映射。

## 2. 文字和动作角色

优先复用 `appearance-themes.css` 已有 `--home-card-*`、`--home-copy`、`--home-muted`、`--home-nav-*`、`--home-action-*`。仅当一个旧 token 同时承担冲突角色时才拆出语义 token。主标题/品牌仍可占最高强调档，面板标题、状态值、计数与常态动作不再全部复用该档。

| 角色 | 第一版建议 | 校准重点 |
| --- | --- | --- |
| Hero 主标题 | 保持现有衬线与 400 字重 | 留作视觉锚点；与正文拉开层级 |
| 项目卡片标题 | 现有 `font-serif-display`，400–440，约 15.5–16px | 以实际平台字体与中英长标题观察，避免系统粗体 |
| 正文/项目说明 | 现有 UI 无衬线，400 | 灰度柔和且可读，避免与标题接近同样明亮 |
| 诗句/辅助标签 | 较弱文字色；维持可识别字号 | 当前已有较低对比度，不能统一再压暗 |
| 状态值/面板计数 | UI 无衬线，500 | 普通信息，不与主标题同权重 |
| 桌面导航 | 共享 token 先试 14px/500/0/1.2 | active/hover/focus 只通过色彩、背景、下划线表达 |
| 卡片动作 | UI 无衬线，500，保留可触达尺寸 | 静态动作降低亮度与填充饱和度，交互态清晰可见 |
| 移动底部标签 | 保持独立的小字号合同 | 不直接套桌面字重；仅在证据支持时调整并同步其测试 |

这些是实现起点，不是未经浏览器验证的最终视觉签名。轻衬线是推荐默认；若用户选择保留无衬线，标题改为现有 UI 字体的约 500 字重，其余角色和验证范围不变。

| 主题 | 文字方向 | 控件与面板方向 |
| --- | --- | --- |
| Stellar | 少量浅亮标题，灰蓝正文、灰紫辅助；避免常态按钮使用最亮冷白 | 降低常态青色按钮与金色边框的强调；保留星空背景与可辨分类色 |
| Morning | 保留深蓝墨色，主要通过字重和角色分层改善 | 保持晨曦材料；先测量，再决定是否需要放松文字色 |
| Nature | 保留深绿墨色，建立与 Morning 对应的角色层级 | 维持自然主题识别，避免全部强调色变成同一种绿 |

不预设“对比度必须低于某数值”的上限。要求必要文字至少 4.5:1，并通过真实截图判断层级；不得为了变柔而违反阅读底线。Stellar 先收敛一版，再把相同角色投影到 Morning/Nature。只在面板与文字不能兼顾时微调相关表面透明度，不通过修改背景渲染器补偿。

## 3. 长标题与卡片节奏

- 先以桌面约 108–112px 的统一卡片高度验证当前最长标题，最终取能容纳标题、说明和上下留白的较小稳定值；具体值与 CSS 中的行高/循环周期来源保持一致。
- 正文列继续可收缩，保留序号与可触达动作区。移除导致文字越出可用行高的局部限制，必要时调整现有 gap/padding，不能全局缩小字体。
- 标题完整换行；说明延续现有摘要语义，不新增截断来掩盖空间问题。移动端使用自适应高度，保持现有 authored 内容、完整/紧凑动作标签规则和 44px 目标。
- 保持 Hero 主结构、8px 圆角与轮播交互。面板高度/可见卡片数作为整体节奏检查，不为照搬参考截图强行加宽页面或改项目内容。
- 轮播 JS 已按真实卡片高度测量周期，本任务默认只改 CSS；若发现现有测量不能处理新的尺寸，先记录证据并更新本设计，再考虑最小产品代码变更。

## 4. 验证设计

新增一个可单独运行的 `scripts/check-home-typography-ui.mjs`，在现有完整 UI 适当分组接入；复用浏览器、网络 guard、三主题和语言来源。断言真实分类映射、文字与容器矩形、角色层级及背景对比度，不把“token 与自己相等”当作覆盖有效的证明。

| 层次 | 覆盖 | 证据 |
| --- | --- | --- |
| 首页视觉 | 三主题 × 两语言 × 1440/320/390/430，共 24 组 | 前后截图、computed style、可见矩形、分类颜色 |
| 真实字体 | Windows 桌面代表样本 | CDP 平台字体、字重和长标题宽高 |
| 背景与可读性 | 静态稳定帧、正常动画代表帧、CSS fallback | 实际合成背景采样；与现有声明色合同同时通过，不夸大为所有未来帧保证 |
| 共享导航 | 六类公共路由；原导航矩阵与 769–1024 中间宽度检查保留 | 五项文字签名、active 几何、hover/focus/route-switch 无跳变 |
| 轮播与输入 | 原 24 配置运动、33 场景缩放专项及相关旧断言 | 自动滚动、惯性、原生缩放、模式切换、内容和 DOM 保持 |
| 交付门禁 | lint、build、performance、smoke、完整 UI | 同一最终版本的结果与输入记录 |

浏览器只访问自有本地预览，API 使用原有 fixture，真实模型调用为 0。预览按 PID/创建时间/完整命令/端口记录所有权。正式全量只在视觉方案和相关专项收敛后执行一次；输入不变的成功结果不重复运行。
