# 恢复目录阅读位置与键盘焦点

## Goal

访客从知识库或项目目录打开详情后，可以返回原入口继续浏览；新打开的详情从标题开始阅读。父任务轮次 4，依赖已交付的博客 URL 状态 `9991079a` 和项目分组 `789d0db3`。普通本地规划、实施、验证、提交和归档由当前持续授权覆盖。

## Evidence

博客 8 次基线和项目新增 8 次基线均显示：四种宽度下详情返回链接丢失列表位置，所有返回焦点落在 BODY。浏览器后退虽能恢复位置，仍丢失入口焦点；新进详情会继承列表或落入深层正文。证据在当前 Temp 目录的 `return-position-baseline.json` 与 `project-return-position-baseline.json`，对应各自记录的 build。两类路径都没有恢复逻辑。

## Requirements

- R1：由目录打开详情后，浏览器后退和详情返回链接恢复同一次目录浏览的原入口及阅读位置，继续保留博客栏目/搜索/页码和项目分组；相关同类详情链保持原目录来源。键盘返回原来的卡片或详情按钮，指针卡片导航返回可操作的等价入口。
- R2：新 PUSH 进入博客/项目详情时，在内容就绪后置顶并聚焦标题；同一组件切换到另一详情也生效。POP 回到已读详情保留其已记住的位置，不强制重回顶部。仅改变目录筛选/搜索时不抢焦点或置顶。
- R3：同一尺寸优先保持入口相对视口的位置；改变尺寸后使原入口可见。来源失效、入口缺失或移动分组隐藏原入口时，返回有效目录并聚焦目录标题。刷新、新标签页或记录淘汰后仍可返回规范目录，不承诺恢复旧进程中的精确位置。
- R4：真实 hash 锚点优先于置顶，异步内容就绪后仍可定位。用户已在等待期间操作导航、控件或滚动时，迟到的详情内容不得抢回其焦点/位置；离开路由后取消待执行恢复。
- R5：恢复线索只存在于有上限的当前页面内存；history state 仅携带不透明引用与返回标记。URL 和返回目标继续由既有白名单工具构造，不新增 storage 阅读历史、任意 returnTo、依赖或生产请求。
- R6：作用范围限定为博客/项目目录和详情。保留其他路由、公开内容、analytics/SEO、主题、触控和阅读导航合同；不修改全局 scrollRestoration 或滚动样式，不将标题加入正常 Tab 顺序。
