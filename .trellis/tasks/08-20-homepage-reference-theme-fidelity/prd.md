# 主站三主题参考站视觉还原

## Goal

在保留泊岸现有 React/Vite 架构、公开内容、路由、项目准入和交互可用性的前提下，重新建立首页三个场景的完整视觉系统，使其首先达到参考站三个主题的整体美感、空间层次与材质完成度，再在此基础上保留泊岸品牌与产品内容，而不是继续通过轻微换色或叠加更多噪声来掩盖结构差距。

## User Value

- 三个主题在第一眼就具有明确、协调且不同的视觉气质，而不是同一套深色界面的颜色变体。
- 首页文字、项目板和背景形成统一构图，内容仍然清晰可读，不被纹理、雾气或过暗面板吞没。
- 主题切换带来完整的环境变化，同时保留泊岸项目、状态、CTA、辅助功能与移动端体验。

## Confirmed Facts

### User evidence

- 2026-08-20 提供的三个当前主题截图显示：Garden 整体偏暗绿且背景与面板层级粘连；Stellar 的星空辨识度较高，但内容面板过重、卡片色块杂且整体仍不像参考站；Dusk 使用大面积棕紫与橙黄渐变，但标题、背景和项目板之间的对比与材质关系不够精致。
- 用户明确认为当前三个主题与参考站差距过大、缺少美感，并要求下一批优化先达到参考站效果。

### Reference-source evidence

- 本地参考源码位于 `D:/workspace4Cursor/resourses/沐星埠.html`、`沐星埠_files/styles.css` 和 `home-grain.css`。
- 参考站在首屏绘制前就为 default、nature、stellar 设置不同整页背景；nature 使用浅紫、青绿和植物色场，stellar 使用深蓝、靛紫和青色空间色场，而不是在统一暗色底板上换强调色。证据：`沐星埠.html:26-58`。
- 参考站每个主题拥有独立的 `panel`、`panel-strong`、`ink`、`muted`、Flow UI RGB、亮度、对比度、饱和度、面板 alpha、卡片 alpha、模糊和速度参数。证据：`沐星埠.html:109-126,849`。
- 参考站使用固定 Flow Canvas、grain、主题化面板/卡片，以及 Stellar 专属星场、边缘光和周界流光形成层次。证据：`沐星埠.html:129-147,261-269,849,904-972,1056-1057`。
- 参考站的视觉完成度来自背景、表面、排版、透明度和光效的协同，而不是仅靠星点、雾气或单一 shader。

### Current-site evidence

- 泊岸当前保留一个 `FlowBackground` Canvas，三个静态基础层和主题 profile；这一单 Canvas 与降动效架构必须继续复用。
- 首页仍由 `HeroSplit` 和 `RightScrollCards` 组成，公开项目、状态与 CTA 逻辑不可被参考站布局覆盖。
- `hero-split.css` 中仍存在较多统一的 Hero、面板和卡片基础材质；场景样式主要在 `appearance-themes.css` 与 `flow-pages.css` 上继续叠加，容易出现统一暗底加主题色的结果。
- 当前外观系统把 `light | dark | auto` 与 `dusk | garden | stellar` 作为两个维度，理论上形成六种组合；参考站本身只有 default、nature、stellar 三个完整视觉主题。

## Requirements

### R1. 参考站级主题艺术方向

- 为三个场景分别定义完整的色彩脚本，包括整页主色场、明暗分布、视觉焦点、文字色阶、面板/卡片材质、边框、阴影和局部光效。
- Garden 对应参考站 nature 的清透、浅色、有机和植物感；Stellar 对应参考站 stellar 的深空、蓝紫、青色星光和高质量玻璃层次；Dusk 对应参考站 default 的暖粉、蓝、琥珀光谱与纸/玻璃混合感。
- 不把“更接近参考站”解释为复制参考站品牌、文字、3D Logo、第三方字体文件、外部资源或全局交互代理。

### R2. 构图与表面系统

- 重新平衡背景和内容层级：背景有空间感但不压住标题；项目板形成明确聚焦面但不成为一整块死黑矩形。
- 标题、正文、状态信息、导航和项目卡文字必须使用主题化色阶，而不是统一降低 opacity。
- 项目卡的强调色应服务于信息层级，避免每张卡形成不协调的大色块。
- 导航、Hero、项目板和助手入口必须属于同一主题材质语言。

### R3. 动态与光效

- 保留现有单 Canvas Flow owner，在其上校准参考站式色场、速度、亮度、对比度和主题构图。
- CSS grain、等高线、星图、辉光、周界光只作为主题材质的辅助层；不通过无限叠层替代构图和色彩修正。
- reduced-motion、页面隐藏、低功耗和 Save-Data 契约继续生效。

### R4. 产品与技术边界

- 保留泊岸 Logo、导航、Hero 文案、产品项目、状态、CTA 和公开助手，不复制参考站内容。
- 不引入第二个持续渲染 Canvas、GSAP、Three.js 或新的动画框架。
- 不修改项目发布状态、真实外链、密钥、生产地址或用户已有状态快照。
- 保持 320、390、430、1024 和桌面视口可用，不因追求桌面截图效果破坏移动端阅读。

## Acceptance Criteria

- [ ] 三个主题分别拥有经截图可辨认的独立整页色彩脚本、明暗焦点、面板透明度、卡片材质和文字色阶。
- [ ] Garden 不再表现为深绿色黑面板，而达到参考站 nature 的清亮有机层次；Dusk 不再浑浊发灰；Stellar 不只依靠星点，而具有深空、流光、玻璃和青蓝焦点的完整层级。
- [ ] 在相同桌面视口下，参考站与泊岸的主题对照能说明构图、色彩比例、面板层级和光效已达到同一完成度，同时泊岸内容和品牌保持独立。
- [ ] 项目板、卡片、标题、正文、导航和助手入口在三个主题中均清晰、协调，无低对比、色块冲突或背景吞字。
- [ ] 首页继续只有一个 Flow Canvas，无新增常驻 React 帧更新或第三方动画运行时。
- [ ] `prefers-reduced-motion`、hidden、低功耗和 Save-Data 保持静止/暂停契约。
- [ ] 320、390、430、1024 和桌面视口无横向溢出、遮挡或不可操作 CTA。
- [ ] lint、build、performance、UI smoke、完整 UI 外观矩阵和 `git diff --check` 通过。
- [ ] `public/status/blog-semi-synthetic.json` 保持未暂存且不进入本任务提交。

## Out Of Scope

- 复制参考站文字、产品内容、Logo、3D 品牌动画、第三方资产或调试界面。
- 改写主站项目准入、状态语义、路由或公开助手业务逻辑。
- 以 Figma 静态图替代浏览器内真实效果验证；Figma 可作为设计对照，但生产页面截图与运行时检查是最终证据。

## Resolved Decision

- 保留“明暗模式 × 三个场景”的六组合结构。`dusk / garden / stellar` 决定主要艺术方向，`light / dark / auto` 只负责对比度与材质变体。每个场景必须分别提供浅色和深色 surface/token 配方，不能让明暗模式覆盖场景身份，也不能把六组合压缩成同一套暗色面板。
