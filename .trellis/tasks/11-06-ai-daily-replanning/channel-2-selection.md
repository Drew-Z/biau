# 渠道 2 主用与模型选择

用户新增 `HORIZON_BASE_URL2/HORIZON_API_KEY2`，明确授权优先使用渠道 2、选择稳定且质量较高的模型，原渠道作为备用。分组修正后目录 HTTP 200，列出 8 个模型。读取目录不等于生成成功；不同域名也不能证明底层供应链完全独立。

写作模式：受限真实新闻模型对照 + Codex 原文审阅。渠道地址/key 仅从私有环境读取，不进证据或日志。上一候选轮已用 7/60 次，本轮沿用剩余 53；无测活、空 prompt 或暗中刷新额度。

## 比较与使用边界

- 先比较同组真实 RSS 的技术研究与产品公告各 1 条，复用 Horizon 原生评分和中文摘要，每模型最多 4 次真实 HTTP；依次选 `deepseek-v4.1-flash`（现行基准）、`glm-5.3-flash`、`gemini-3.8-flash-high`。候选名来自第三方目录，不据名称宣称官方能力或长期稳定。
- 维持现行思考设置（不增加关闭思考参数）、24,000 字符/2,048 输出 tokens/60 秒上限。仅明确 400/422 参数兼容可使用剩余额度；已失败或完成请求不得进入隐式重试。候选任何硬错误/预算耗尽即停止该候选，不用备用重发同条。
- 核对中文表达、原文事实和限定条件、厂商归因、评分合理性；完整输出与质量为前提，再比较首片段/总耗时。小样本仅说明本轮表现，不可声称长期稳定率。
- 最佳候选完成完整七源样稿及原文检查后，更新主用配置和 GitHub 环境。旧渠道保留为显式切换备用，避免因偶发 524 自动重发可能已计费请求。
- 主用/备用始终整组读取，不能混用 URL/key/model；恢复检查点必须绑定所选渠道标识与端点指纹。停止或过期的旧检查点不清除、不重试。
- 候选期刊、七源与模型策略验收通过后再合并发布；初始已验收期刊标识保持。普通后续合格期刊沿用既有自动发布授权。

## 2026-11-07 实测结果

目录重新读取 HTTP 200，8 个模型。随后一次直连目录 GET 超时，同期系统代理 GET 约 2.72 秒返回 200；直连与代理不是同一网络条件，不能合并为模型排名或长期成功率。

| deepseek-v4.1-flash | 4 | 直连两项评分 60 秒超时；代理路径用另一条真实新闻完成评分和摘要，10.953 / 11.640 秒 |

最初三候选没有完整样本后，在同一剩余额度内补测另三个通用文本候选，并把 DeepSeek / Gemini High 的未用对照额度用于代理路径另一条真实新闻。每模型仍不超过 4 次对照请求；未调用图像或代码审查专用模型。每个模型/样本/阶段失败后没有自动重发，原生兼容重试本轮未发生。

暂选渠道 2 的 `deepseek-v4.1-flash`，因为它是本轮唯一完成评分与中文摘要、且正文经证据核对通过的候选。不是“最稳定”证明：其后独立的完整七源业务试跑在 4 次请求后停止，顺序为成功、成功、请求超时、连接中断；连续失败阈值生效，没有 bundle。两份成功评分与停止账本保留，不能清除停止状态重跑。
